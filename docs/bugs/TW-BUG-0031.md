# TW-BUG-0031: SMN chart images omit the security identity and use unreadably small text

- Status: verified on dev
- Confidence: reproduced
- Priority: P2. Every SMN daily article shipped charts that did not say which security they showed, and their text rendered at roughly 7-11 CSS px in the article column. Images shared, saved or viewed out of context lost their meaning.
- First observed / last updated: 2026-10-09 23:10 UTC (reported by Afshin) / 2026-10-09 23:50 UTC
- Executor/session/claim time: Claude Code (Opus 5.5), session 6dd54b04-ad02-49d6-9209-84d5b2326727, claimed 2026-10-09 23:15 UTC
- Authorization: Afshin, 2026-10-09: "fix the smn dev". Scope: SMN chart presentation only (`blog/chartkit.py`, `blog/engine_seasonal.py::render_price`, `blog/visual_charts.py`) plus Dev activation. Production is read-only and was not touched. Exclusions: no TradeWave engine math, projection normalization, statistics, or published-revision rewrites.

## User Impact and Reproduction

Environment before the fix: SMN main/Dev runtime `185af5cbec060a41958650c1bc709cfc68f0946d`. Evidence edition: `/var/tmp/smn-production-native-d69c46e/run-32bd869/web/editions/2026-10-05/*/assets` on 192.168.1.180.

1. `tradewave-price_projection{,-mobile}.png` had no title, symbol, security name, window or source inside the image. Text was plain DejaVu at 11 pt / 160 dpi on a 1600 px canvas, and the legend was 8-9 pt.
2. `business-context-{desktop,mobile}.png` (visual_charts) had no title, subject, security or source inside the image.
3. `tradewave-bars*.png` on desktop had tick, year and source text around 8-9 CSS px. The mobile variant omitted the security name, and its source line was about 7 CSS px.
4. The mobile bar spec labelled every non-midterm cohort "consecutive windows", which is wrong for election, post-election and pre-election cohorts. Silver futures (resource 7) were labelled "Share price (USD)".

## Evidence and Investigation

- `render_price` has been plain matplotlib since `354c7d2` (2026-09-10). `visual_charts.render_chart` put the title only in HTML.
- The chartkit frame was tuned for a 1280 px canvas at DPI 100, and the article column (max-width 740 px) displays it at about 0.58x. Phone images display at about 0.46x.
- The projection overlay's normalized scaling is the owner-approved design (`docs/TRADEWAVE_ECOSYSTEM.md`, owner clarification 2026-09-12). It is out of scope and unchanged. Only its labels changed: it is now called the "normalized" seasonal trend and "not a forecast", and no percentage, target or endpoint is printed.
- The 2026-10-09 manual opinion article "Two clocks, one date" (publishing receipt `8b2e42f0...`, tags manual/opinion) has four hand-made charts that were uploaded with the article, not generated by SMN. This fix does not change them.

## Acceptance and Regression Checks

- Every generated chart shows `SYMBOL · Security name` in the image header. The price chart and context charts also carry a title, subtitle and source line inside the image.
- At article width, text is at least ~10.5-12 CSS px on desktop and ~10-11 CSS px on phones. Tests enforce at least 18 image px on desktop and 22 on mobile for every text artist.
- Header, plot and footer never overlap (tested). Long titles and sources wrap before shrinking. Long security names drop letter-spacing instead of shrinking. Year ticks thin out based on measured label width.
- The price chart plots the owner's closes and projection points unchanged (tested), shades the studied window, and names the last close in the legend.
- Tests: `test_chartkit test_engine_seasonal test_visual_editorial test_seasonal_price_path test_seasonal_edition test_editorial_gate`: 95 OK (87 before, plus 8 new). Full suite: 1092 run. The 34 failures/errors are identical to untouched main `185af5c` (pre-existing environment errors when run as `flask`), so there are no regressions.
- Visual review: desktop and mobile renders were inspected for AMZN, NVDA, QQQ, SI, SPY, XLF (Oct 5) and ADP, FDS, IWM, MSFT, SPX, XLK (Oct 2), plus the legacy trend, cumulative, stats and fork renderers.
- Not run: browser/Playwright pixel review of a newly published article. Already published dev revisions keep their reviewed, hash-bound images. New generations use the new renderer.
