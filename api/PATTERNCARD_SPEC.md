## Hard invariants (carry over - never violate)
- PATTERNS ONLY. No raw OHLCV / last price / price-by-date / price levels anywhere. All
  monetary movement is expressed as PERCENTAGES. The seasonal curve `index` is a 0-100
  normalized relative shape, never a price.
- `historical_win_rate` (share of profitable years, from ChartData4 'Percent Profitable',
  0..1) and `ml_win_prob` (the ML model's predicted probability, Pro-only, 0..1) are
  DISTINCT fields with DISTINCT names. NEVER both called "win rate". This is a known footgun.
- ML fields are Pro-tier + ML-eligible-market (ids 0,1,2,3,4,11) only; null-not-absent for
  others, with a tier nudge. Never error on a free caller.
- `years` and seasonal-window labels stay STRINGS. Market ids are the permanent keys '0'..'16'.
- IMPERSONAL + disclaimed (regulatory, publisher exclusion). Every card carries `disclaimer`.
  Outputs are uniform per market (same pattern to everyone); never tailored to a user's
  portfolio. The exact disclaimer string is below.
- Fail-fast on real errors (contract Error JSON); fail-soft ONLY on genuine per-symbol data
  gaps (degrade that row, log, never 500 the list).

## 1. The PatternCard object (THE unit; built once, server-side, in apiserver/cards.py)

Returned by /v1/scan, /v1/analyze/{symbol}, and /v1/daily-pick. The gateway pre-composes
`headline` + `verdict` so weak agents render consistently; it also ships structured fields so
strong agents can rank/compare/explain.

```jsonc
{
  "rank": 1,                                  // pre-sorted by the endpoint; agent never sorts
  "symbol": "GLD",
  "market": { "id": "11", "name": "ETFs" },
  "direction": "long",                        // long | short
  "bias": "bullish",                          // bullish | bearish | neutral  (neutral => low conviction; see sec 4)
  "setup": {
    "entry_date": "2026-07-12",
    "entry_window": "2026-07-08 to 2026-07-15",   // tolerance, not a single magic day (+/- a few trading days)
    "hold_days": 18,
    "exit_date": "2026-07-30"
  },
  "edge_score": 82,                           // 0-100 blended; see sec 3. explainable.
  "edge_basis": "win_rate 0.80 x sharpe 1.4 x 10y history",  // human-readable why
  "stats": {
    "historical_win_rate": 0.80,             // share of profitable years (Percent Profitable)
    "sharpe_ratio": 1.4,
    "avg_return_pct": 6.2,
    "median_return_pct": 5.1,
    "years": "10"                             // lookback label (string)
  },
  "ml": {                                     // null unless Pro + ML-eligible market (0-4,11)
    "ml_score": 71,
    "ml_win_prob": 0.68,                      // DISTINCT name from historical_win_rate
    "pred_return_pct": 5.4,
    "pred_mfe_pct": 8.1
  },
  "receipts": {                               // sec 2 - the trust layer; ALWAYS present on a bullish/bearish bias
    "years_tested": 10,
    "wins": 8,
    "losses": 2,
    "historical_win_rate": 0.80,
    "avg_return_pct": 6.2,
    "median_return_pct": 5.1,
    "best_year": { "year": "2019", "return_pct": 14.3 },
    "worst_year": { "year": "2022", "return_pct": -4.1 },
    "per_year": [ { "year": "2024", "return_pct": 7.1, "result": "win" }, ... ],  // one row per lookback year
    "curve_summary": { "shape": "rises into entry, peaks ~day 14, fades", "peak_day": 14, "trough_day": 31 },
    "source": "TradeWave seasonal model, 10y lookback",
    "as_of": "2026-05-31"
  },
  "next_step": {                              // sec 5 - the no-broker last mile
    "headline": "To act on this, here is a ready-to-place ticket:",
    "order_ticket": {                         // broker-agnostic, copyable, NO price level
      "side": "BUY", "symbol": "GLD", "type": "MARKET", "time_in_force": "DAY",
      "suggested_entry_date": "2026-07-12", "suggested_exit_date": "2026-07-30",
      "note": "Seasonal hold ~18 calendar days. Size to your own risk."
    },
    "copy_text": "BUY GLD market, day order; plan exit ~2026-07-30 (18d seasonal hold).",
    "set_reminder": { "type": "seasonal_entry", "fire_on": "2026-07-11", "message": "GLD seasonal window opens tomorrow." },

  },
  "headline": "GLD long - enter ~Jul 12, hold 18d. Won 8/10 years, avg +6.2%, Sharpe 1.4.",

```

Rules:
- `headline` + `verdict` MANDATORY, gateway-composed. No em-dashes (use ' - ').
- `per_year` capped at the lookback length; NEVER ship the 365-point curve inline (only
  `curve_summary` here; the full curve stays at the /v1/seasonal-chart primitive).
- `next_step.order_ticket` carries NO price level and NO limit price in absolute terms (TIF/
  side/type/dates/note only) - stays inside the no-raw-prices invariant.
- `ml` is null (not omitted) for free/non-eligible; set `tier_notes` to the nudge.

## 2. Receipts (build from existing data)
- `historical_win_rate`, `wins`, `losses`, avg/median, best/worst year, and `per_year[]` come
  from ChartData4's per-year returns + 'Percent Profitable' (the appserver already computes
  these; the gateway already reads stats via _chart_data/_win_rate_from_stats). per_year needs
  the per-year ChartData4 entries (year, net%) -> result = win if net% > 0 (no threshold, matches
  the UI). `curve_summary` is derived from the /v1/seasonal-chart normalized curve (peak/trough
  day + a one-line shape description). source/as_of stamped by the gateway.
- For the DAILY PICK card, receipts ALSO include the live forward-tested record (count, win_rate,
  avg_return) from featured_history - the strongest receipt (made in advance, scored later).

## 3. edge_score - the blended ranking (documented + explainable)
edge_score = round(100 * clamp01( 0.40*win_rate_n + 0.30*sharpe_n + 0.20*ml_n + 0.10*history_n )) where:
- win_rate_n  = historical_win_rate (already 0..1)
- sharpe_n    = clamp(sharpe_ratio / 3.0, 0, 1)        // 3.0 Sharpe = full marks
- ml_n        = ml_win_prob if (Pro AND ml present) else win_rate_n   // non-Pro: ML term falls back to win_rate so ranking still works
- history_n   = clamp(years_tested / 15.0, 0, 1)       // 15y history = full marks
Set `edge_basis` to the dominant factors in words. This formula is a v1 default and is
DOCUMENTED in the response/docs so it is explainable; it is tunable later (do not hardcode in
multiple places - one function in cards.py).

## 4. neutral bias / low conviction
When the best available setup is weak (edge_score < 40 OR historical_win_rate < 0.55 OR
years_tested < 5), return `bias: "neutral"` with a short `verdict` explaining why ("no
high-conviction seasonal edge here right now") and OMIT next_step.order_ticket (nothing to
act on). This conflict-free honesty is a differentiator - never manufacture a setup.

## 5. New gateway endpoints

### GET /v1/scan  -> find_best_opportunities (the flagship scanner)
Scan across the caller's in-scope markets, rank by edge_score, return PatternCards.
Query params:
- markets   (optional, csv of ids or names e.g. "2,11" or "gold,energy"; default = ALL in-scope)
- window    (optional: "now" | "next_2_weeks" | "next_month" | a from..to; default "now")
            "now" = setups whose entry_date falls within the next ~10 trading days.
- direction (optional: long|short)
- min_win_rate (optional 0..1; filters on historical_win_rate)
- min_years (optional int; trust filter - require >= N years_tested)
- rank_by   (optional: edge|win_rate|sharpe|ml|avg_return; default edge)
- limit     (optional; tier-capped to opp_limit)
Response: { generated_at, window, rank_by, count, evaluated_count, enrichment_capped(bool),
            opportunities: PatternCard[] }
Implementation: fan out over /v1/opportunities per in-scope market (reuse appserver_client.
opportunities), resolve window->entry dates, enrich+score+rank, attach ML inline for Pro on
eligible markets, build PatternCards. PARALLELIZE the per-market fan-out (ThreadPoolExecutor);
enrich win_rate AFTER ranking/slicing so we never fan out 50xN. Surface evaluated_count +
enrichment_capped so the min_win_rate cap is never silently misleading (P0 bug fix).

### GET /v1/analyze/{symbol}  -> analyze_symbol (the bundled deep-dive)
One symbol -> one rich PatternCard (best setup) + other setups + receipts + (Pro) ml, fused
server-side from /OppBySymbol + ChartData4 stats + consolidated_seasonal_chart2 (+ MLScore).
Query: market (optional - resolve if unique), direction (optional), days_out (optional).
Response: { card: PatternCard, other_setups: [ {compact setup+stats} ], as_of }
Kills the 4-tool stitch and guarantees win_rate consistency.
